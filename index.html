Build your Wayfinder Hub

In this multi-session lab, each exercise adds a connected module to one web application. Start with a dashboard, then add knowledge cards, a quiz, a STEM journey, a story map, creative media, data, challenges, and games. Earlier work becomes the content for later exercises, so your application grows with you.

Prerequisites

Before you start, make sure you have:

  • A computer, Chromebook, or tablet with a modern web browser (Chrome, Edge, or Firefox)
  • An internet connection
  • A free GitHub.com account (Step 1 below)
  • Access to GitHub Copilot (through your school, GitHub Education, or GitHub Copilot Free)
  • Several class sessions, with one working module completed in each session

Nothing needs to be installed. For a 90-minute sampler, build the Hub foundation and one core module.

1Create your GitHub.com account

  1. Go to github.com/signup.
  2. Enter your email address, create a password, and choose a username.
  3. Verify your email using the code GitHub sends you.
  4. If your school provides GitHub Education or Copilot access, ask your teacher for sign-up instructions so Copilot is enabled on your account.

Already have an account? Sign in and skip ahead to Step 2.

2Get your own copy of this project

  1. Open the repository at github.com/berryst2/wayfinders-vibe-coding-lab.
  2. In the top-right corner of the page, select the Fork button.
  3. On the “Create a new fork” screen, you can keep the repository name as it is or give it your own short name, for example my-wayfinders-app.
  4. Leave Copy the main branch only checked.
  5. Select Create fork.
  6. GitHub will open your new copy of the project under your own account.

You now have your own copy of the project. Every change you make from here happens in your copy, not the original. Forks are public by default, which is what you need for free GitHub Pages publishing later.

3Open your project in GitHub Codespaces

  1. In your new repository, select the green Code button.
  2. Select the Codespaces tab.
  3. Select Create codespace on main.
  4. Wait about a minute while your coding environment loads in the browser.
  5. You should see index.html, style.css, script.js, and the prompts folder in the file list on the left.
  6. Open a terminal (Terminal menu → New Terminal) and run python3 -m http.server 8080 to preview your site.
  7. When the Ports tab pops up at the bottom, select the globe icon next to port 8080 to open your app in a new tab.

Codespaces gives you a full coding environment inside your browser tab. There is nothing to install on your own computer.

4What is “vibe coding”?

Vibe coding means describing what you want in plain English and letting GitHub Copilot write the HTML, CSS, and JavaScript for you. You focus on the idea and the experience. Copilot focuses on the code. You still read the result, test it, and ask for changes until it feels right.

You: Build a quiz about navigation with a score counter.
Copilot: Updates index.html, style.css, and script.js, then explains what changed and what to test.
You: Make the score bigger and add a restart button.
Copilot: Adjusts the styles and adds the restart feature.

Open Copilot Chat in Codespaces (the chat icon in the left sidebar) to start a conversation like this one.

How to paste your prompt into Copilot Chat in VS Code

Your Codespace is really Visual Studio Code running in the browser, so Copilot Chat works the same way it would on a computer.

  1. Select the Copilot Chat icon in the left sidebar of your Codespace (or press Ctrl+Alt+I).
  2. At the bottom of the Chat panel, make sure Agent mode is selected so Copilot can edit your files directly.
  3. Select a prompt card above, then select Copy prompt in the panel that slides in from the right.
  4. Click inside the Copilot Chat box, paste the prompt, and press Enter to send it.
  5. Copilot will create or update files inside app. Review the changes it made, then select Keep to apply them.
  6. Open or refresh /app/ in your preview tab to see the result.

Paste one prompt at a time. Read what Copilot changed, then preview your app before asking for the next change.

8Publish with GitHub Pages


      
Commit and push your changes to your fork

      
    
        
  1. Select the Source Control icon in the left sidebar of your Codespace (it looks like a branch).
    2. 
        
  2. Hover over Changes and select the + icon to stage all your edited files.
    3. 
        
  3. Type a short commit message in the box at the top, for example Build my first version.
    4. 
        
  4. Select the checkmark (Commit) button.
    5. 
        
  5. Select Sync Changes (or Push) to send your commit to your forked repository on GitHub.com.
    6. 
      

      
Pushing sends your code to your fork, not the original lab repository, so it is always safe to commit and push.


      
Turn on GitHub Pages

      
    
        
  1. Go to your repository on GitHub.com.
    2. 
        
  2. Select Settings → Pages.
    3. 
        
  3. Under Build and deployment, choose Deploy from a branch.
    4. 
        
  4. Set the branch to main and the folder to / (root), then select Save.
    5. 
        
  5. Wait a minute, then refresh the Pages settings screen to see your live link.
    6.
